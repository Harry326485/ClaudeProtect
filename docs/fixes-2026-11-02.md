# 设置编辑器、洛杉矶默认值与语言修复

## 设置编辑器

托盘的 Edit settings 和 Open log 使用内置 Win32 文本窗口，避免依赖启动时报告缺少 `Microsoft.UI.Windowing.Core.dll` 的系统记事本。设置窗口支持 Ctrl+S、保存前配置校验、原子替换及关闭时的未保存提示；日志窗口只读。CLI `--edit-settings` 只打开托盘和设置窗口，不启动 Claude。

已验证：构建通过；`scripts/test-settings.ps1` 覆盖缺省配置、洛杉矶映射、UTF-8 中文文本保存、非法时区/语言/模式拒绝、失败时保留原文件、临时文件清理。本轮未完成编辑窗口的可视操作验证。

## 默认时区

默认值和本机 `build/ClaudeProtect.ini` 均为：

```ini
Timezone=Pacific Standard Time
TimezoneIana=America/Los_Angeles
Locale=en-US
```

父/子原生探针报告一月偏移 −480 分钟、七月 −420 分钟，即 PST/PDT。没有修改宿主时区、语言或注册表。

## 语言调用链

原有自检只检查用户/系统 Win32 首选语言，未检查线程首选语言或 WinRT。补充观测后，在旧 DLL 上复现：

- 用户和系统首选语言：`en-US`。
- 线程首选语言：`zh-CN;zh-Hans;zh;en-US`（合并回退列表还含 `en`）。
- WinRT `GlobalizationPreferences.Languages`：`zh-Hans-CN;en-US`。

[Electron 44.9.3 源码](https://github.com/electron/electron/blob/v44.9.3/shell/common/language_util_win.cc) 显示 `app.getPreferredSystemLanguages()` 优先读取 WinRT，失败时才使用线程首选语言。只补线程钩子不足以覆盖这条路径。

补丁在 LEP 模式 2 增加线程 Win32 导出钩子，并包装目标 WinRT 激活工厂的 `IGlobalizationPreferencesStatics`，让 Languages 返回配置语言。其他工厂保持原行为；Calendars/Clocks/Currencies/HomeGeographicRegion/WeekStartsOn 委托给原对象。独立探针检查 Electron 使用的 Size/GetAt 路径，并检查 IndexOf、GetMany、边界及字符串释放。

验证结果：

| 探针 | 时区/语言 | 父/子 WinRT 结果 | 结果 |
| --- | --- | --- | --- |
| x64，自检 | Los Angeles / en-US | en-US / en-US | 通过 |
| x64，自检 | Tokyo / ja-JP | ja-JP / ja-JP | 通过 |
| x86，匹配 x86 加载器 | Los Angeles / en-US | en-US / en-US | 通过 |
| x64，UI 模式 1 | Los Angeles / en-US | 按旧模式保留 WinRT 宿主值 | 兼容自检通过 |

上游四套 public-api、timezone、lepb-compat、broker-handle 测试均通过。匹配架构的测试驱动位于 `tests/lep-language-launch.cpp`。直接使用 x64 加载器启动 x86 探针不是这份语言验证的通过路径；该路径曾报告宿主语言和子进程创建错误，未在本次任务中修复。

原始探针 JSON 已归档至 [验证记录索引](verification/README.md)，包括 `2026-11-02/la-en-us-x64.jsonl`、`tokyo-ja-jp-x64.jsonl`、`la-en-us-x86.jsonl` 与 `host.json`。独立宿主探针仍报告 `China Standard Time` / `zh-CN`，WinRT 首选语言仍为 `zh-Hans-CN;en-US`。

## 验证边界

初次实测只补线程钩子的版本时，Claude 的进程字段仍包含宿主首选语言，因此增加了 WinRT 补丁。用户要求不再启动 Claude 后，已结束测试会话；最终 WinRT 补丁仅通过独立探针验证，未重新启动 Claude，也未确认最终界面文字或实际应用字段。Claude 单独保存的界面语言设置优先于自动语言检测。历史 renderer/Worker JS 证据仍来自 Edge 代理，不能当作本次 Claude 的直接观测。
