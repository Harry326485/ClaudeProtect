# Architecture and validation

ClaudeProtect owns only processes it launches into its Job Object. It must never kill processes by executable name. An already running unmanaged Claude instance must cause launch refusal because Electron single-instance forwarding can bypass supervision.

The selected backend is the pinned LocaleEmulatorPlus-Core submodule. The integration calls `LepCreateProcess2` with `CREATE_SUSPENDED`, assigns its returned process to a kill-on-close Job Object, then resumes the primary thread. LEP prepares early injection and propagates its configuration to children. Closing the last job handle kills managed descendants, including after supervisor failure. The tray remains alive when Claude exits. Stop explicitly terminates the job; normal main-process exit also triggers cleanup of remaining helpers. The adapter, preflight probe, and runtime verification are implemented in `src/lep.cpp`, `src/probe.cpp`, and `src/session.cpp`, and have been exercised against a native LEP build. See `implementation.md` and `lep-verification-2026-10-29.md`.

Timezone and locale have two observation layers: native Windows APIs and Electron/V8/ICU. Environment variables and Chromium switches alone are hypotheses, not proof. A native probe and renderer diagnostics record actual observations. Host settings are read only. Upstream LEP logs child injection failures and still returns successful process creation; ClaudeProtect adds a parent/child preflight probe, per-process injection-record/log checks, and external-helper classification, and stops the job in strict mode. LEP Core is manually mapped and invisible to module enumeration, so verification uses its injection records and initialization logs rather than `GetModuleHandle`.

Integration patches are published under [patches/lep](../patches/lep/README.md) and applied to the pinned submodule before building. Dynamic time-zone queries use `CP_TIMEZONE`, `GetACP`/`GetOEMCP` and UI/preferred-language exports are virtualized, and mode 2 covers thread and WinRT preferred languages. Public LEPB v4 is unchanged. ClaudeProtect appends `--lang=<Locale>` for Claude Desktop because Chromium's language selection follows that switch. Residual host values are documented in `lep-verification-2026-10-29.md`, with later language verification in `fixes-2026-11-02.md`.

No elevation, services, drivers, VM, executable patching on disk, global hooks, sandbox disabling, or permanent host setting changes.
